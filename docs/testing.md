# Проверка решения

Проверено 14 сентября 2026 года на Windows 11 x64, сборка ОС 22631.
Чистая Release-сборка выполнена из отдельной копии исходников, без предыдущего
каталога сборки и без зависимостей проекта, установленных глобально.

## Среда

- C++17, GCC 16.2.0 из w64devkit 2.9.1.
- CMake 4.4.3, генератор MinGW Makefiles, GNU Make 4.4.1.
- `-Wall -Wextra -Wpedantic`; предупреждений при сборке не получено.
- PowerShell 5.1 для демонстрации; Python 3 для интеграционных проверок.
- Приложения импортируют только системные `KERNEL32.dll`, `msvcrt.dll`, `WS2_32.dll`.

Конфигурация Visual Studio 2022 предусмотрена CMake и описана в README, но MSVC
в этой среде не установлен. Фактическая проверка компиляции выполнена с MinGW-w64.
Осмотр кода не заменяет проверку другим компилятором.

## Повторение проверок

Для Visual Studio после сборки:

```powershell
ctest --test-dir build -C Release --output-on-failure
python tests/integration.py --bin-dir build/Release --output-dir test-output
python tests/native_console.py --bin-dir build/Release --output-dir test-output
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/demo.ps1 -BinDir build/Release
```

Для MinGW заменить `build/Release` на `build-mingw`, а первую команду на:

```powershell
ctest --test-dir build-mingw --output-on-failure
```

Python 3 нужен только для двух дополнительных сценариев; они используют
стандартную библиотеку, установка пакетов не требуется. Проверки CTest
самодостаточны. Автотесты выбирают свободные localhost-порты; демо по умолчанию
использует 14550/14551 и позволяет изменить их через `-DronePort`/`-GroundPort`.

`native_console.py` проверяет реальные Windows-события клавиатуры и Ctrl+C
в отдельных скрытых консолях созданных им процессов. Консоль вызывающего
терминала остается подключенной; тест не вводит текст в другие приложения.
Дополнительный случай `Dashboard` читает настоящий экранный буфер GCS: проверяет
закрепленный ввод при четырех обновлениях телеметрии, отображение NACK,
отправку набранного GOTO, длинную строку и уменьшение окна до 60×15 символов.

## Что именно проверяется

**Протокол:** независимо рассчитанный ARM-пакет, точный little-endian layout
GOTO/TELEMETRY/NACK, отсутствие padding, усечение пакетов, повреждение каждого
байта, лишние байты, неверные magic/длина при корректном checksum, переполнение
суммы checksum, NaN/Infinity, географические границы и неизвестные enum.

**Модель:** начальное состояние, ARM, повторный новый ARM, условия GOTO,
скорости и ограничение шага целью, расход батареи, RTL, отмена цели на DISARM,
запрет DISARM при CRITICAL и неверные payload команд.

**GCS:** CLI без лишних аргументов, ошибки чисел, общий seq, перестановка и
дубликаты, переход uint32 через ноль, предел окна статистики, таймауты и
корреляция ACK/NACK по обоим полям команды.

**Интеграция:** реальные приложения и UDP-датаграммы, построенные независимо
с помощью Python `struct`; повтор ARM не применяется заново; конфликт содержимого
при том же seq отвергается. Полный полет проверяется по CSV, а не только
по строкам ACK. Сетевой ввод, отсутствие ответа, закрытие stdin и ошибки запуска
проверяются ограниченным ожиданием завершения процесса.

## Исправления, подтвержденные регрессиями

При независимом ревью найдены и исправлены два случая: EOF мог отменять принятые
команды до отправки, а удаление табуляции могло менять смысл строки. Тесты
воспроизвели оба случая до исправления; после исправления прошли. Повторное
ревью не выявило ошибок синхронизации в измененных путях.

Отдельный тест настоящей консоли выявил наследуемое игнорирование Ctrl+C.
При запуске теперь регистрируется обработчик и явно включается обработка сигнала.
Тест передает дочернему процессу унаследованный запрет и проверяет корректный
выход. Это поведение Windows описано в
[документации Microsoft](https://learn.microsoft.com/en-us/windows/console/ctrl-c-and-ctrl-break-signals).

При проверке панели также воспроизведено объединение повторяющихся клавиш
Windows в одно событие. Ввод теперь учитывает `wRepeatCount`: одинаковые цифры
в координатах и удерживаемый Backspace не теряются.

## Материалы демо

В `docs/demo` сохранены консольные логи и CSV фактического прогона Release-сборки.
Пути к рабочим каталогам в текстовом логе сокращены до имени файла; значения
телеметрии, номера пакетов и время не изменены. Это текстовые логи, а не скриншоты.

Проверки подтверждают поведение в описанных сценариях. Они не являются доказательством
отсутствия всех возможных ошибок и не проверяют реальное летное оборудование.
