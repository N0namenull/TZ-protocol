# DroneSim и GCS по UDP

Два консольных приложения для Windows на C++17: симулятор дрона и наземная станция.
Они обмениваются телеметрией и командами через собственный бинарный UDP-протокол.
Для приложений нужны только стандартная библиотека C++, Windows API и Winsock.

GCS использует **два потока**: главный обслуживает ввод, рабочий — сеть, команды,
статистику и CSV. В DroneSim один цикл обслуживает модель и неблокирующий сокет.

В обычной консоли GCS показывает обновляемую панель: телеметрию и статистику
сверху, приглашение `gcs>` внизу окна.

## Сборка

### Visual Studio 2022

Установить Visual Studio 2022 Community или Build Tools 2022 с компонентом
**Desktop development with C++**, включая MSVC, Windows SDK и CMake tools for Windows.
Открыть **Developer PowerShell for VS 2022**, перейти в корень распакованного проекта:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

Результат: `build\Release\DroneSim.exe` и `build\Release\GCS.exe`.
Эта конфигурация предусмотрена проектом; фактическая проверка в среде разработки
выполнена с MinGW-w64, а не с MSVC.

### MinGW-w64

Альтернатива — переносимый [w64devkit](https://github.com/skeeto/w64devkit/releases)
и [CMake](https://cmake.org/download/). Распаковать инструменты, добавить их каталоги
`bin` в PATH текущего PowerShell. Например, если они распакованы в `C:\tools`:

```powershell
$env:Path = "C:\tools\w64devkit\bin;C:\tools\cmake\bin;" + $env:Path
cmake -S . -B build-mingw -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++ -DCMAKE_MAKE_PROGRAM=make
cmake --build build-mingw --parallel
ctest --test-dir build-mingw --output-on-failure
```

Указать фактический путь к CMake: имя его распакованного каталога может содержать
версию. Для другого дистрибутива MinGW, где есть только `mingw32-make`, заменить
`-DCMAKE_MAKE_PROGRAM=make` на `-DCMAKE_MAKE_PROGRAM=mingw32-make`.
Результат: `build-mingw\DroneSim.exe` и `build-mingw\GCS.exe`.
Не использовать один каталог сборки для разных генераторов или компиляторов.

Никакие зависимости при сборке не скачиваются. Python нужен только для
дополнительного интеграционного теста, PowerShell — для автоматического демо.

## Запуск вручную

Открыть два терминала в корне проекта. Ниже пути для Visual Studio;
для MinGW заменить `build\Release` на `build-mingw`.

Терминал 1:

```powershell
.\build\Release\DroneSim.exe
```

Терминал 2:

```powershell
.\build\Release\GCS.exe --log flight.csv
```
Если запускать без ключа ```--log```, то лог будет всё равно писаться, но в файл telemetry.csv

Параметры по умолчанию:

| Параметр | Значение |
|---|---|
| Адрес обеих программ | `127.0.0.1` |
| DroneSim принимает команды | UDP `14550` |
| GCS принимает телеметрию и ответы | UDP `14551` |
| Старт | широта `55.750000`, долгота `37.610000`, высота `0` м |
| Начальное состояние | DISARMED, MANUAL, yaw `0°`, батарея `100%` |
| Скорость | горизонтальная `10` м/с, вертикальная `3` м/с |
| Периоды | TELEMETRY около `100` мс, HEARTBEAT около `1` с |

## Демонстрационный сценарий

После появления `TELEMETRY` вводить в GCS команды по одной, дожидаясь ACK:

```text
arm
mode 1
goto 55.751000 37.610000 15
```

Подождать несколько секунд. Широта должна увеличиваться от `55.750000` к
`55.751000`, высота — от `0` к `15` м. Затем:

```text
disarm
```

Дождаться `ACK DISARM` и строки телеметрии с `armed=0`. Завершить GCS командой
`quit`, DroneSim — `Ctrl+C`. Файл `flight.csv` останется в текущем каталоге.

Автоматическое демо выполняет тот же сценарий и проверяет результат:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -BinDir .\build\Release
```

Для MinGW указать `-BinDir .\build-mingw`. Политика применяется только к этому
запуску PowerShell. Демо сохраняет `flight.csv`, `gcs.txt`, `dronesim.txt` и ошибки
в новый каталог под `demo-output`. Оба процесса запускаются скрыто; их консольный
вывод сохраняется. Для показа в живых окнах использовать ручной сценарий выше.

В `docs/demo` лежат результаты фактического прогона. Полный набор проверок и
сведения о проверенной сборке описаны в [docs/testing.md](docs/testing.md).

## Команды GCS

| Команда | Назначение |
|---|---|
| `status` | Текущая телеметрия и статистика, с текущими настройками работу команды не видно, потому что и так обновление статуса происходит каждую секунду |
| `arm` | Арм дрона; повторный новый ARM получает NACK BUSY |
| `disarm` | Дизарм, отменить цель полёта; запрещено при CRITICAL |
| `mode 0` | MANUAL; отменить цель |
| `mode 1` | GUIDED; разрешить GOTO |
| `mode 2` | RTL; у armed-дрона установить цель в стартовую точку |
| `goto <lat> <lon> <alt>` | Задать цель; требуются ARM и GUIDED |
| `help` | Мини-подсказка |
| `quit` | Завершить GCS, отменив ожидающие команды |

Разделитель дробной части — точка. Допустимы только конечные числа: широта
`[-90,90]`, долгота `[-180,180]`, высота `[0,10000]` м. Лишние аргументы отвергаются.
ACK для GOTO означает, что цель принята; завершение движения видно по телеметрии.

При отсутствии ACK/NACK GCS повторяет **те же байты и seq** через 750 мс;
максимум два ретрая. После трех попыток печатается TIMEOUT. Команды отправляются
по очереди: следующая — после ответа или таймаута предыдущей. `status` и `quit`
обрабатываются во время ожидания. TIMEOUT не доказывает, что команда не выполнена:
ответ мог потеряться, поэтому состояние следует проверить по телеметрии.

## Аргументы запуска

Обе программы:

| Аргумент | Значение |
|---|---|
| `--bind <IPv4>` | Локальный адрес, по умолчанию `127.0.0.1` |
| `--peer <IPv4>` | Адрес второй программы, по умолчанию `127.0.0.1` |
| `--listen-port <n>` | Собственный UDP-порт, `1..65535` |
| `--peer-port <n>` | UDP-порт второй программы, `1..65535` |
| `--duration <секунды>` | Автоматическое завершение; `0` без ограничения, максимум `86400` |
| `--help` | Справка |

Только DroneSim: `--speed`, `--vertical-speed` (обе скорости `>0` и `<=1000` м/с),
`--start-lat`, `--start-lon`, `--start-alt`.
Только GCS: `--log <путь>`, по умолчанию `telemetry.csv`.
Родительский каталог лога должен существовать. Файл с этим именем **перезаписывается**
при старте; для сохранения разных полетов указывать разные имена.

Пример другой пары портов:

```powershell
.\build\Release\DroneSim.exe --listen-port 15550 --peer-port 15551 --speed 5
.\build\Release\GCS.exe --listen-port 15551 --peer-port 15550 --log flight-15551.csv
```

Обе стороны проверяют адрес и порт отправителя. Ошибка в `--peer-port` приведет
к игнорированию пакетов и таймаутам. DNS-имена и IPv6 не поддерживаются.

## Потоки и завершение

**GCS:** главный поток читает события консоли или данные перенаправленного stdin.
Он передает строки в очередь под `std::mutex`. Рабочий поток единолично владеет
сокетом, ожидающей командой, статистикой и файлом CSV. Очередь ввода ограничена
128 строками, очередь сетевых команд — 64 командами, строка — 1024 байтами.
При переполнении выводится ошибка; длинная строка не выполняется частично.

**DroneSim:** один цикл сначала обновляет модель по `steady_clock`, затем
обрабатывает ограниченное число пакетов и отправляет периодические сообщения.
Временные метки CSV используют системное время UTC, таймеры — монотонные часы.

Два потока нужны для независимого ввода и сети. От взаимной блокировки защищают
более конкретные решения: отсутствие вложенных захватов mutex, короткие операции
с очередью, отсутствие сетевых вызовов под ее блокировкой, неблокирующие сокеты
и ожидания с таймаутом. Ошибка рабочего потока устанавливает флаг остановки;
главный поток замечает его даже без нажатия Enter и выполняет `join()`.
Ресурсы освобождаются через RAII. Выход проверен по quit, EOF, `--duration` и Ctrl+C
в настоящей консоли Windows, в том числе с унаследованным запретом Ctrl+C.

Панель использует отдельный экранный буфер Windows. Перерисовка и изменения
ввода защищены одним mutex, поэтому сетевой поток не затирает набираемый текст.
При изменении размеров окна строка ввода остается внизу; длинная команда
прокручивается горизонтально внутри своей строки. В узком окне часть статуса
может не поместиться; для полного просмотра достаточно расширить окно.
После выхода восстанавливается экран оболочки и печатается итоговое сообщение.

При перенаправлении stdin или stdout используются обычные текстовые строки,
без перерисовки панели. CSV всегда содержит полный поток актуальной телеметрии.
Поддержаны обычный ввод, повтор клавиш, Backspace, Enter и Ctrl+C, без истории
команд и редактирования стрелками. `quit` отменяет оставшиеся команды.
При EOF GCS сначала обрабатывает принятые команды, дожидаясь ACK/NACK или исчерпания
ретраев каждой команды, затем закрывает лог и завершается. Поэтому завершение
конечного ввода при недоступном борте может занять около 2.25 с на команду.

## Статистика и CSV

GCS обновляет телеметрию и статистику на панели раз в секунду (или печатает строки
при перенаправлении вывода); логирует каждую принятую
актуальную телеметрию, то есть примерно 10 строк/с.

- `rx` — корректные сообщения ожидаемого отправителя, включая дубликаты.
- `unique`, `lost`, `loss` — уникальные пакеты, пропуски и процент потерь по общему seq.
- `invalid`, `foreign` — неверные пакеты и пакеты чужого адреса/порта.
- `duplicates`, `late`, `stale` — дубликаты, переставленные и слишком старые сообщения.
- `heartbeat_age` — секунды с приема последнего нового HEARTBEAT; `never`, если его еще не было.

Потери считаются от первого принятого seq: `100 * lost / expected`.
Seq общий для TELEMETRY, HEARTBEAT, ACK и NACK. Окно 4096 номеров позволяет
исправлять счетчик потерь при поздней доставке и не считать дубликаты новыми.
До поступления задержанного пакета потери могут быть временно завышены.
Переход uint32 через ноль поддержан. Пропажу последних пакетов до появления
следующего seq обнаружить этим способом нельзя.

CSV содержит:

```text
timestamp,seq,lat,lon,alt,yaw,battery,armed,mode
```

`timestamp` — время получения в UTC, `armed` — 0/1, `mode` — 0/1/2.
Телеметрия, пришедшая позже более новой телеметрии, учитывается в статистике,
но не откатывает отображение и не добавляется в CSV. Ошибки открытия/записи лога
завершают GCS с ненулевым кодом, а не оставляют работающую программу без лога.

## Протокол и принятые допущения

Полная раскладка: [docs/protocol.md](docs/protocol.md).

- Используется заданное число magic `0x44524F4E` в little-endian — байты
  `4E 4F 52 44`. Подпись «DRON» в ТЗ не совпадает с таким порядком байт;
  приоритет отдан числу и явно указанному little-endian.
- На корректно оформленную команду возвращается ACK/NACK. Пакет с неверным
  magic, длиной или checksum отбрасывается. Неверный payload команды дает INVALID_ARGS.
- DroneSim хранит результаты последних 128 команд не дольше 10 секунд.
  Повтор seq с тем же содержимым возвращает прежний результат без выполнения.
  Совпавший seq с другим содержимым дает INVALID_ARGS. Ответ имеет новый seq борта.
- Идентификатора сессии в ТЗ нет. Для нового запуска GCS следует перезапускать
  и DroneSim, чтобы не столкнуться с кешем старых команд. При перезапуске DroneSim
  также перезапустить GCS, чтобы начать статистику последовательности заново.
- DISARM уже разоруженного дрона разрешен; новый ARM уже вооруженного — BUSY.
  SET_MODE разрешен и без ARM. GOTO проверяет аргументы, затем ARM, затем GUIDED.
- MANUAL, DISARM и установка режима отменяют предыдущую цель. RTL возвращает
  к исходным координатам и высоте без автоматического DISARM.

## Модель и ограничения

Движение — локальная плоская аппроксимация Земли: расстояния по широте/долготе
переводятся в метры, шаг ограничивается оставшимся расстоянием. Для долготы
выбирается короткий переход через ±180°. Высота меняется отдельно с вертикальной
скоростью. Это учебная модель для коротких перемещений; она не предназначена
для точной геодезии, больших дистанций и полюсов.

Батарея уменьшается на 0.1 процентного пункта в секунду, пока дрон armed,
даже если он стоит. При батарее <=5% выставляется CRITICAL, движение прекращается,
ARM/GOTO/DISARM запрещаются с OTHER. Это условная логика из ТЗ; для восстановления
нужен перезапуск симулятора. BOOT предусмотрен протоколом, но после запуска
симулятор сразу готов и передает STANDBY.

UDP не гарантирует доставку и порядок. Адресная фильтрация не является
аутентификацией, checksum не является криптографической защитой. Проект рассчитан
на обмен по localhost. Карты, GUI, MAVLink, аэродинамика и настоящий автопилот
в проект не входят.
